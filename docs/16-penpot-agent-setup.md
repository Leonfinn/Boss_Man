# Penpot: let agents read your designs (owner steps)

You do this once, after Penpot is running (see [15-penpot.md](15-penpot.md)). No coding. Agents can read what the agent account can see, and draw only in the "Agent designs" project of their own team and in files they create themselves.

1. **Make the agent account.** Open Penpot in your browser (`http://<your server's address>:9001`). Registration is normally closed; the install notes in 15-penpot.md say how to open it briefly. Register a new account for the agents, for example `agents@penpot.local`, with a long random password you keep in your password manager.
2. **Give the agents their own team, and keep them read-only in yours.** Penpot sets roles per team, not per project, so an Editor in your team can change every file in it. Log in as the agent account and use its own team (the one called `Default`), or make a new team there. In that team make a project called `Agent designs` (agents can also make it themselves). Invite yourself to that team as a member (use your own email), so the links agents print open for you. Then, logged in as yourself, open your own team, find the agent account under **Members** and set its role to **Viewer**: it can read your designs but cannot change or delete anything. Agents draw only in their own team. Open `Agent designs` there to see what they drew.
3. **Make the access token.** Log in as the agent account. Click its name (bottom left) > **Your account** > **Access tokens** > **Generate new token**. Name it `boss-man`, choose an expiry (90 days is a good start; put the renewal date in your calendar), and create it. Copy the token now: Penpot shows it only once.
4. **Save it in Boss Man.** Open **Settings → Tools → Penpot** for the company and choose **Set up Penpot**. Fill in **Penpot address** (the address the runners reach it on, with its port, for example `http://192.168.1.20:9001`) and paste the token into **Access token**. Never paste the token into a ticket, chat or file.
   **For PNG export only:** Penpot's export service cannot use an access token; it needs a login. Fill in **Export email** (the agent account's email) and **Export password** (its password) too. Without them everything else works but `export` says what is missing.
5. **Choose the agents, then save.** Under **Agents who use Penpot**, tick the agents who need designs (for example the Designer and the Developer). Under **Agents who export PNGs**, tick only the agents that actually export boards, not everyone who holds the token. Leaving every box unticked gives it to every agent in the company, so tick at least one. Then choose **Save Penpot**.

   Boss Man opens Penpot's address in the network guard for that company's runner by itself, from the address you saved: there is no `.env` line to add, and it stays open after updates and restarts. **Settings → Server and runner → Network guard** lists it under *Allowed automatically*. A LAN address (a private IP such as `192.168.1.20`, or a name with no dot or ending in `.lan`, `.local`, `.home` or `.internal`) is trusted to stay private; a public name is opened only while it points at a public address.

   Note: this setup assumes Penpot is on a private network. The address is plain http, so the password (which cannot be revoked like a token) travels unencrypted; put Penpot behind HTTPS before it is ever reachable beyond that network.

   **Set up before this form existed?** Nothing to do: the form reads the `PENPOT_URL`, `PENPOT_TOKEN`, `PENPOT_EMAIL` and `PENPOT_PASSWORD` secrets you granted on the Secrets screen and shows Penpot as already set up. If you added Penpot's address to `BOSSMAN_NETGUARD_ALLOW` in `.env` by hand, the Network guard page now marks that entry "already allowed by Boss Man" and you can remove it from the line the next time you edit `.env` (leaving it does no harm).
6. **Give them the skill.** In Skills, add the `penpot` skill (paste this link: https://github.com/Leonfinn/Boss_Man/tree/main/skills/penpot), then give it to the same agents.
7. **Try it.** Make a ticket for one of those agents: "Create a file called Test in Agent designs with a desktop board and a mobile board, each with a heading, and give me the link." If the agent says it isn't set up, check steps 4 and 5 (is the agent ticked?); if it reports a permission error, check step 2 (the agent account must own its own drawing team). If it can't connect at all, check that the Penpot card shows "the network guard opens" Penpot's host:port. If export fails, check the export email and password.

**When the token expires or leaks:** in Penpot, delete the token under Your account > Access tokens, make a new one, and paste it into **Settings → Tools → Penpot → Change Penpot → Access token**.

**If the export password leaks:** in Penpot, signed in as the agent account, change its password (Your account > Password), then paste the new one into **Change Penpot → Export password**. The password must be unique to that account and used nowhere else. Keep the account Viewer in your own team: unlike a token, a password gives control of the whole account.
