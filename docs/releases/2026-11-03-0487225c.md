# Release notes: 3 Nov 2026, 0487225c

What changed for you, and anything you must do.

## What changed for you

### One permission card, not two (BOS-376)

Sometimes an agent asks Boss Man for the same permission twice in quick
succession: a retry, or the same command reported once for the folder and once
for the command. You used to get two identical cards. Now:

- If the second ask arrives while the first card is still waiting, it joins
  that card. The card says a repeat was asked, and your one answer covers
  both.
- If you already pressed **Allow once** and the same request comes back within
  five minutes in the same run, it is answered with that allow. No second card
  appears, and the first card records what settled it.
- **Deny is never treated as Allow.** A repeat after a deny is a new card, and
  a deny for a repeat waiting on a card reaches that repeat as a deny.
- Matching is exact: same run, same tool, and the whole request the same. A
  fetch pointed at a public page and the same tool pointed at a home-network
  address are different requests, and the second still gets its own card.
  Nothing carries from one run to another.

## What you must do

Nothing.

## Known issues

- A repeat is only covered within the same run and within five minutes of an
  allow; a deliberate rerun later is a new question.
- The audit shows the repeat next to the card that settled it, not as a
  separate card.

## Rollback point

The commit this release replaced is `d86dbe1f`. Roll back with
`host-deployer.sh --rollback` run by hand as root. This change has no database
migration, so the previous release runs on the same schema unchanged.
