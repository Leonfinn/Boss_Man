# Release notes: 3 Nov 2026, d86dbe1f

Fuller notes for the entry in [[releases/release-log]]. Owner-facing.

## What changed for you

### Copy buttons now copy (BOS-336)

The Copy button on a hand-apply card, or on any card that shows a command to
paste, used to do nothing when Boss Man is opened over plain http on your LAN
(the browser only allows copying on https pages). It now copies anyway, and if
copying still fails it selects the text for you and says
"Couldn't copy, select the text instead". On a phone, a long button label no
longer squeezes the command into a sliver.

### A second Claude Max plan, used automatically (BOS-383)

You can now put your Claude subscriptions in an order on the Funding page
("Switch between Claude accounts", order 1 = used first). When one plan reaches
your hold level, new runs start on the next one with room, and go back to the
first once it resets. Each switch is announced once in your notifications. Runs
already going finish on the plan they started on.

**What you must do if you want to use a second plan:**

1. Get that plan's Claude setup-token.
2. Settings > Secrets > Add secret, kind "Claude setup-token".
3. Funding page, add (or open) that plan's subscription source.
4. Set "Order" (1 or 2) and pick its login from "Login for this account".

The first account does not need its own token; it keeps using the company's
existing Claude token. Every account after the first needs its own login, or it
is skipped. Nothing changes if you leave the list empty.

## Known issues

- A run started before the switch stays on the old plan until it finishes; a big
  run can keep using the first plan's quota for a while.
- The switch is by hold level, not by a hard weekly-limit signal, so the first
  plan can still be "full" for a short time before new work moves.

## Rollback point

The commit this release replaced is 2d5e3035. Roll back with
`host-deployer.sh --rollback` run by hand as root. On a blue/green install the
automatic switch-back also covers the window right after a swap. The database
migration is expand-only, so the previous release runs on the new schema.
